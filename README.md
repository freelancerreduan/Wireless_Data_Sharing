# Reduan Smart Info — v0.1.0

একটি অফলাইন ডিজিটাল বিজনেস কার্ড অ্যাপ (Kotlin + Jetpack Compose + Material 3)। ইউজার নিজে অ্যাপের ভেতর থেকে প্রোফাইল তৈরি করেন, কোন তথ্য শেয়ার হবে তা ঠিক করেন, তারপর QR, NFC ট্যাগ, Bluetooth (অ্যাপ ইউজারদের মধ্যে), .vcf ফাইল অথবা Wi-Fi/হটস্পট দিয়ে শেয়ার করেন। Wi-Fi শেয়ারে প্রাপকের ফোনে অ্যাপ লাগে না, শুধু ব্রাউজার লাগে।

## Build ও Run

1. Android Studio (Ladybug বা নতুন) দিয়ে `ReduanSmartInfo` ফোল্ডারটি খুলুন। Gradle sync নিজে থেকেই Gradle 8.9 ডাউনলোড করবে।
2. ফিজিক্যাল ফোনে Run করুন। Bluetooth, NFC আর হটস্পট এমুলেটরে ঠিকমতো টেস্ট করা যায় না।
3. কমান্ড লাইন থেকে চালাতে চাইলে আগে wrapper তৈরি করতে হবে, কারণ `gradle-wrapper.jar` এই প্যাকেজে নেই:
   ```
   gradle wrapper --gradle-version 8.9
   ./gradlew assembleDebug        # APK: app/build/outputs/apk/debug/
   ./gradlew testDebugUnitTest    # unit tests
   ./gradlew installDebug
   ```

## Profile ও তথ্য ব্যবস্থাপনা

- কোডে কোনো নাম, ফোন, ইমেইল, ঠিকানা, কোম্পানি, ছবি বা লিংক hardcode করা নেই। সব তথ্য Edit profile স্ক্রিন থেকে ইউজার নিজে দেন।
- ফিল্ডগুলো হলো: নাম, পদবি, কোম্পানি, ফোন, ইমেইল, ঠিকানা, ব্যবসার বিবরণ, ওয়েবসাইট, Facebook, LinkedIn, Instagram, WhatsApp, YouTube। এর বাইরে লেবেলসহ সর্বোচ্চ ১০টি নিজস্ব লিংক যোগ করা যায়।
- Add / Edit / Delete (ফিল্ড খালি করলে মুছে যায়) / Save / Discard changes / Reset (পুরো প্রোফাইল মুছে ফেলা, কনফার্মেশন নিয়ে)। সেভ না করে বের হতে চাইলে সতর্কবার্তা দেখায়।
- Validation:
  - নাম বাধ্যতামূলক।
  - ফোন নম্বরে ৭–১৫টি ডিজিট থাকতে হবে, '+' শুধু শুরুতে বসতে পারে।
  - ইমেইলের ফরম্যাট চেক হয়।
  - URL শুধু http/https গ্রহণ করে। `javascript:` বা `ftp:` ধরনের লিংক বাতিল হয়। "example.com" লিখলে নিজে থেকে https:// যোগ হয়।
  - প্রতিটি ফিল্ডে দৈর্ঘ্যের সীমা আছে, আর control character মুছে ফেলা হয়।
- স্টোরেজ: Jetpack DataStore আর ছবির জন্য app-private ফোল্ডার। অ্যাপ বন্ধ করে আবার খুললেও তথ্য থাকে। `allowBackup=false`, তাই ক্লাউড ব্যাকআপে যায় না।
- ফিল্ড-লেভেল শেয়ারিং: My Card স্ক্রিনে প্রতিটি আইটেমের আলাদা সুইচ আছে। ফোন, ইমেইল, ঠিকানা আর WhatsApp ডিফল্টভাবে বন্ধ থাকে।
- সব শেয়ারিং মাধ্যম একটি `ShareableProfile` থেকে তৈরি হয়। এটা সেভ করা প্রোফাইল থেকে স্বয়ংক্রিয়ভাবে বানানো হয়। ফলে Save বা কোনো সুইচ বদলালে QR, NFC, BLE, vCard আর Wi-Fi সবকিছু সাথে সাথে নতুন তথ্য ব্যবহার করে, এমনকি চলমান Bluetooth বা Wi-Fi সেশনও। কোনো চ্যানেলে বাছাই না করা তথ্য যাওয়ার উপায় নেই।

## কোন ফিচার কীভাবে কাজ করে (সত্যিকারের সীমাবদ্ধতাসহ)

| NFC ট্যাগে লেখা ও পড়া | ✅ | ওয়েবসাইট লিংক অথবা vCard লেখা যায়, লেখার আগে কনফার্মেশন নেয়। Android Beam ব্যবহার হয় না, কারণ ফোনে-ফোনে ছুঁয়ে পাঠানো Android থেকে সরিয়ে দেওয়া হয়েছে |
| Bluetooth (Nearby / Very Near) | ✅ শুধু অ্যাপ ইউজারদের মধ্যে | Advertisement-এ কোনো ব্যক্তিগত তথ্য থাকে না, শুধু random session id। RSSI দূরত্বের আনুমানিক ধারণা দেয়, সঠিক দূরত্ব নয়। প্রাপক আগে preview দেখে, তারপর Save to contacts চাপে |
| Wi-Fi/হটস্পট শেয়ার (প্রাপকের অ্যাপ লাগে না) | ✅ | লোকাল HTTP সার্ভার শুধু Wi-Fi বা হটস্পট IP-তে চলে। থাকে random token, ৫ মিনিট মেয়াদ, Accept/Reject বাটন, একবার ব্যবহারযোগ্য ডাউনলোড লিংক। **এনক্রিপ্টেড নয়** (plain HTTP) |
| হটস্পট নিজে থেকে চালু করা | ❌ | Android-এ সেটা সম্ভব নয়, ইউজারকে Settings থেকে চালু করতে হবে |
| ব্যাকগ্রাউন্ডে Bluetooth | ❌ | অ্যাপ স্ক্রিন থেকে সরে গেলে সব শেয়ারিং বন্ধ হয়ে যায় (foreground service যোগ করা হয়নি) |
| যেকোনো ফাইল পাঠানো, অ্যাপের ভেতরে QR স্ক্যান, শেয়ারিং হিস্ট্রি, PIN, বাংলা UI | ❌ পরবর্তী ধাপে | ড্যাশবোর্ডে এগুলোর জন্য কোনো ভুয়া বাটন রাখা হয়নি |

## Testing

**স্যান্ডবক্সে আসলে যা চালানো হয়েছে:**
- ২৬টি JVM ইউনিট টেস্ট পাস করেছে (`app/src/test`)। কভার করে: validation, শেয়ারিং ফিল্টার, vCard তৈরি, escaping ও folding, link codec, BLE chunking, proximity classifier, আর লোকাল সার্ভারের পুরো Accept → download → replay-block, Reject ও expiry ফ্লো।
- সব Kotlin ফাইলের syntax check করা হয়েছে।

**যা চালানো হয়নি:**
- পুরো APK build। স্যান্ডবক্স থেকে Google Maven-এ পৌঁছানো যায়নি, তাই Compose/Android অংশ কম্পাইল হয়নি।
- এমুলেটর বা ফিজিক্যাল ফোনে কোনো টেস্ট।

প্রথম build-এ ছোটখাটো কম্পাইল এরর আসতে পারে।
